# Spec Delta

## MODIFIED Requirements

### Requirement: 月単位カレンダー表示

システムは、労務報告状況を月単位のカレンダーで表示しなければならない（SHALL）。各日には始業・終業のステータスと zac 状態を表示する。zac 状態は、zac 保存成功日時が設定済みなら「zac済」、最新の実行結果が `validation_failed`・`needs_login`・`failed`・`already_registered_in_zac` のいずれかなら「要対応」、それ以外は表示なしとする。月のカレンダーの取得で、各日の最新の実行結果を日ごとに個別に問い合わせてはならない（MUST NOT）。

#### Scenario: 当月のカレンダーを開く

- **WHEN** ユーザーがカレンダー画面を開く
- **THEN** システムは当月の各日を表示し、各日に対応する `work_report` のステータス（未報告／始業記録済み／終業記録済み／メール作成済み）と zac 状態を示す

#### Scenario: 別の月へ移動する

- **WHEN** ユーザーが前月・翌月へ移動する
- **THEN** システムは選択された月の各日のステータスと zac 状態を表示する

#### Scenario: zac 登録済みと要対応

- **WHEN** 10/8 は zac 保存成功日時が設定済み、10/9 は最新の実行結果が `needs_login`
- **THEN** システムは 10/8 に「zac済」、10/9 に「要対応」を表示する

### Requirement: 未報告日の強調表示

システムは、報告が未完了の過去日（`not_started` または始業のみ等）を視覚的に強調しなければならない（MUST）。あわせて、zac 保存成功日時が未設定の過去の平日（出退勤実績の区分が休暇の日を除く）も強調しなければならない（MUST）。

#### Scenario: 未報告の過去日を強調する

- **WHEN** カレンダーに記録のない過去の平日が含まれる
- **THEN** システムはその日を未報告として強調表示する

#### Scenario: zac 未登録の過去営業日を強調する

- **WHEN** 終業メール作成済みだが zac 保存成功日時が未設定の過去の平日がある
- **THEN** システムはその日を zac 未登録として強調表示する

### Requirement: 本日の報告画面

システムは、当日の始業・終業報告を行う「本日の報告」画面を提供しなければならない（SHALL）。当日の始業時刻・終業時刻・勤務時間・メモを表示し、記録操作の起点とする。画面には業務明細として、ジョブ選択・内容入力と「タスク開始」「休憩開始」「停止」「休憩終了」「再開」「既定の休憩を追加」「行を追加」の操作、タスクと休憩を開始時刻順に並べた一覧（開始・終了・ジョブ・内容・時間、編集・削除）、作業と休憩の合計時間を表示しなければならない（SHALL）。進行中のタスク・休憩は終了時刻の代わりに進行中であることを示さなければならない（SHALL）。自由記述の「業務報告」入力欄は表示してはならず（MUST NOT）、代わりにメール作成の領域に `{{tasks}}` の展開結果を読み取り専用・コピー可能なプレビューとして表示しなければならない（SHALL）。カレンダーから過去日を開いた場合も、同じ画面でその日の業務明細を編集できなければならない（SHALL）。画面には打刻（laborman）とは別に出退勤（人事メール）の出勤・退勤時刻・登録元・取込日時を表示し、未登録の場合は「未取込」、区分が休暇の場合は「休暇」と表示しなければならない（SHALL）。出退勤の「手入力」操作から出勤・退勤・区分を入力・上書きできなければならない（SHALL）。画面には zac 登録パネルとして、その日のドラフト（入力行と実働時間）、検証結果（重要度ごと）、既定の休憩の提案、最新の実行結果（日時・モード・状態・スクリーンショットのパス）を表示しなければならない（SHALL）。パネルの内容はエージェントが使うドラフトと同一でなければならない（MUST）。

#### Scenario: 本日の報告画面を表示する

- **WHEN** ユーザーが本日の報告画面を開く
- **THEN** システムは当日の日付、始業報告/終業報告の操作、記録済みの始業時刻・終業時刻・勤務時間・メモ、業務明細の操作と一覧、作業・休憩の合計時間を表示する

#### Scenario: カレンダーから本日の報告へ遷移する

- **WHEN** ユーザーがカレンダー上で本日の報告操作を選ぶ
- **THEN** システムは本日の報告画面を表示し、その場で始業・終業を記録できる

#### Scenario: 過去日の業務明細を編集する

- **WHEN** ユーザーがカレンダーで 2026-10-09 を選ぶ
- **THEN** システムは 2026-10-09 のタスクと休憩を一覧表示し、行の追加・編集・削除を受け付ける

#### Scenario: 重なりエラーを表示する

- **WHEN** ユーザーが既存のタスクと重なる行を保存しようとする
- **THEN** システムは保存されなかったことと、重なっている相手の時間帯を画面に表示する

#### Scenario: 業務報告欄の代わりにプレビューを表示する

- **WHEN** ユーザーが本日の報告画面でメール作成の領域を見る
- **THEN** システムは自由記述の「業務報告」入力欄を表示せず、当日のタスクから生成した `{{tasks}}` のプレビューとコピー操作を表示する

#### Scenario: 出退勤が未取込の日

- **WHEN** ユーザーが当日の報告画面を開き、出退勤実績がまだ登録されていない
- **THEN** システムは出退勤（人事メール）を「未取込」と表示し、打刻（laborman）の時刻は別の行に表示する

#### Scenario: 出退勤を手入力する

- **WHEN** ユーザーが出退勤の「手入力」から出勤 09:00・退勤 18:30 を入力して保存する
- **THEN** システムは出退勤実績を登録元 `manual` で保存し、画面に 09:00 – 18:30 と手入力であることを表示する

#### Scenario: zac 登録パネルを表示する

- **WHEN** ユーザーが 2026-10-09 の報告画面を開く
- **THEN** システムは zac 登録パネルに、ドラフトの API と同じ入力行（例：JOB-A 5:00 / JOB-B 3:30）、実働時間、検証結果、最新の実行結果を表示する
