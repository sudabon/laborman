# Spec Delta

## MODIFIED Requirements

### Requirement: ジョブマスタの管理

システムは、ジョブ ID（zac の案件の JOB 番号）・表示名（zac の案件名）・zac 検索文字列・既定の作業内容・シリーズ名・対象年月・有効/無効を保持するジョブマスタを提供し、設定画面で追加・編集できなければならない（SHALL）。ジョブ ID は一意でなければならない（MUST）。ジョブは削除せず無効化で扱う。zac 検索文字列が未設定の場合は、ジョブ ID で zac の案件を検索する。

#### Scenario: ジョブを追加する

- **WHEN** ユーザーが設定画面でジョブ ID `2601570`・表示名「サービス開発本部 make.AI 業務」を入力して保存する
- **THEN** システムはジョブマスタに `2601570` を有効な状態で保存する

#### Scenario: 重複したジョブ ID

- **WHEN** すでに `2601570` がある状態で、同じジョブ ID のジョブを追加しようとする
- **THEN** システムは `409` を返し、既存のジョブを変更しない

### Requirement: タスク入力時のジョブ選択

システムは、タスク入力時のジョブ候補を最近使った順に提示し、ジョブ ID・表示名・シリーズ名によるインクリメンタル検索で絞り込めなければならない（SHALL）。シリーズ名を持つジョブ（月ごとに JOB 番号が変わる案件）は、シリーズ名で 1 つの候補として提示し、保存時にタスクの勤務日の年月を対象年月とするジョブに置き換えなければならない（SHALL）。該当する年月のジョブがない場合は、未登録である旨を表示して保存してはならない（MUST NOT）。タスクの作成に使われたジョブは最近使った順の先頭に移動しなければならない（SHALL）。未登録のジョブ ID を入力した場合は、その場でジョブマスタに登録できなければならない（SHALL）。タスクには登録済みのジョブ ID しか指定できない（MUST）。

#### Scenario: 最近使ったジョブが先頭に出る

- **WHEN** 直前に 2600901 でタスクを追加し、次にジョブ候補を開く
- **THEN** システムは 2600901 を候補の先頭に表示する

#### Scenario: 月ごとの案件をシリーズで選ぶ

- **WHEN** シリーズ「bizoceanAPPs開発」に 2602062（対象年月 2026-10）と 2602063（対象年月 2026-11）があり、ユーザーが 2026-11-05 の業務明細で「bizoceanAPPs開発」を選んでタスクを追加する
- **THEN** システムはタスクのジョブ ID を 2602063 として保存する

#### Scenario: その月の案件が未登録

- **WHEN** シリーズ「bizoceanAPPs開発」に 2026-12 の案件がない状態で、2026-12-01 のタスクを「bizoceanAPPs開発」で追加しようとする
- **THEN** システムは「2026 年 12 月の bizoceanAPPs開発 の案件が未登録です」と表示し、タスクを保存しない

#### Scenario: 未登録のジョブ ID を入力する

- **WHEN** ユーザーがジョブ選択で未登録の `2609999` を入力する
- **THEN** システムは表示名を入力して `2609999` を登録する操作を提示し、登録後にそのジョブでタスクを作成できる

#### Scenario: 存在しないジョブ ID でタスクを保存する

- **WHEN** API に未登録のジョブ ID でタスクの保存を要求する
- **THEN** システムは `422` を返し、タスクを保存しない

## ADDED Requirements

### Requirement: 売上項目

システムは、ジョブごとに zac の売上項目の選択肢（名前・対象年月・売上計上済みかどうか・有効/無効）を保持し、設定画面で追加・無効化できなければならない（SHALL）。対象年月は、売上項目名に含まれる年月表記（`（2026／10）`・`(26/10)`・`（2026年8月分）` など）から読み取らなければならない（SHALL）。売上項目は同じジョブの中で名前が一意でなければならない（MUST）。

#### Scenario: 月ごとの売上項目

- **WHEN** ジョブ 2602028 に売上項目「プロジェクトサポート（2026／10）」を登録する
- **THEN** システムは対象年月を 2026-10 として保存する

#### Scenario: 作業の種類を表す売上項目

- **WHEN** ジョブ 2600901 に売上項目「社内管理業務」「外部研修」を登録する
- **THEN** システムは対象年月なしで両方を保存し、2600901 のタスクでどちらも選べる

### Requirement: 作業内容

システムは、zac の作業内容の選択肢（例：プロジェクト作業・プロジェクト関連打ち合わせ）を保持し、設定画面で追加・無効化できなければならない（SHALL）。作業内容の名前は一意でなければならない（MUST）。

#### Scenario: 作業内容を追加する

- **WHEN** ユーザーが設定画面で作業内容「プロジェクト業務（レビュー）」を追加する
- **THEN** システムはタスク入力時の作業内容の選択肢に「プロジェクト業務（レビュー）」を表示する

### Requirement: zac のマスタの取込と更新

エージェントは、`laborman-agent sync-zac` で zac の作業登録の画面から、作業内容の選択肢、案件の候補（JOB 番号と案件名）、案件ごとの売上項目の選択肢と売上計上済みの印を読み取り、laborman のマスタに追加・更新しなければならない（SHALL）。読み取りの間、エージェントは zac の「登録」「保存」「確定」を操作してはならず（MUST NOT）、開いた作業登録の画面は取り消して閉じなければならない（MUST）。取込は追加と更新だけを行い、zac の候補に現れなかったジョブ・売上項目を自動で無効化してはならない（MUST NOT）。zac の候補には過去月の案件が残るため、対象年月が読み取りに使った日の月より前の案件は取り込んではならない（MUST NOT）。案件ごとの売上項目は、その案件を選んだあとに zac が売上項目を読み込み終えてから読まなければならない（MUST）（前の案件の選択肢を読まないため）。同じ案件名で年月表記だけが異なるジョブは、年月表記を除いた名前をシリーズ名、年月を対象年月として登録しなければならない（SHALL）。システムは、取込の内容を一括で登録する API を提供しなければならない（SHALL）。

期替わりなどで JOB 番号が新しく払い出された場合は、利用者と zac の画面を確認したうえで取込を行い、使わなくなったジョブを無効化する（運用手順として `agent/README.md` に記載する）。

#### Scenario: 月替わりの案件を取り込む

- **WHEN** zac の案件の候補に「2602063 bizoceanAPPs開発(26/11)」が追加された状態で `sync-zac` を実行する
- **THEN** システムはジョブ 2602063（シリーズ「bizoceanAPPs開発」・対象年月 2026-11）と、その売上項目を登録し、zac には何も保存しない

#### Scenario: 過去月の案件は取り込まない

- **WHEN** 2026-10-14 に `sync-zac` を実行し、zac の候補に「2602061 bizoceanAPPs開発(26/09)」「2600733 第26期 XDG運営業務(26/08)」が残っている
- **THEN** システムはこれらの案件と売上項目を取り込まず、取り込まなかった件数を結果に表示する

#### Scenario: 候補から消えた案件

- **WHEN** 前回取り込んだ 2602061 が zac の案件の候補に現れない状態で `sync-zac` を実行する
- **THEN** システムは 2602061 を無効化せず、候補に現れなかった旨を結果に表示する
