# Spec Delta

## Purpose

タスクに付けるジョブ ID と、zac 上で案件を選ぶための情報を一元管理し、タスク入力時のジョブ選択を素早く正確に行えるようにするための機能。

## ADDED Requirements

### Requirement: ジョブマスタの管理

システムは、ジョブ ID（zac の案件コード）・表示名・zac 検索文字列・zac 作業分類・有効/無効を保持するジョブマスタを提供し、設定画面で追加・編集できなければならない（SHALL）。ジョブ ID は一意でなければならない（MUST）。ジョブは削除せず無効化で扱う。

#### Scenario: ジョブを追加する

- **WHEN** ユーザーが設定画面でジョブ ID `JOB-A`・表示名「A社保守」・zac 検索文字列「A社 保守」を入力して保存する
- **THEN** システムはジョブマスタに `JOB-A` を有効な状態で保存する

#### Scenario: 重複したジョブ ID

- **WHEN** すでに `JOB-A` がある状態で、同じジョブ ID のジョブを追加しようとする
- **THEN** システムは `409` を返し、既存のジョブを変更しない

### Requirement: タスク入力時のジョブ選択

システムは、タスク入力時のジョブ候補を最近使った順に提示し、ジョブ ID・表示名によるインクリメンタル検索で絞り込めなければならない（SHALL）。タスクの作成・開始に使われたジョブは最近使った順の先頭に移動しなければならない（SHALL）。未登録のジョブ ID を入力した場合は、その場でジョブマスタに登録できなければならない（SHALL）。タスクには登録済みのジョブ ID しか指定できない（MUST）。

#### Scenario: 最近使ったジョブが先頭に出る

- **WHEN** 直前に JOB-B でタスクを開始し、次にジョブ候補を開く
- **THEN** システムは JOB-B を候補の先頭に表示する

#### Scenario: 未登録のジョブ ID を入力する

- **WHEN** ユーザーがジョブ選択で未登録の `JOB-C` を入力する
- **THEN** システムは表示名を入力して `JOB-C` を登録する操作を提示し、登録後にそのジョブでタスクを作成できる

#### Scenario: 存在しないジョブ ID でタスクを保存する

- **WHEN** API に未登録のジョブ ID でタスクの保存を要求する
- **THEN** システムは `422` を返し、タスクを保存しない

### Requirement: ジョブの無効化

システムは、無効化されたジョブを新規タスクの候補に表示してはならない（MUST NOT）。無効化は既存タスクの表示・編集に影響させてはならない（MUST NOT）。

#### Scenario: 無効化したジョブ

- **WHEN** JOB-A を無効化した後、JOB-A を使った過去のタスクを表示する
- **THEN** システムは過去のタスクを JOB-A として表示し、新規タスクのジョブ候補には JOB-A を表示しない
