# Spec Delta

## Purpose

勤務日ごとの作業（ジョブ ID・内容・開始・終了）を 1 件ずつのレコードとして記録し、zac 登録や終業メールの元データにするための機能。

## ADDED Requirements

### Requirement: タスクの記録

システムは、勤務日ごとにタスク（ジョブ ID・内容・開始時刻・終了時刻）を複数件記録できなければならない（SHALL）。終了時刻のないタスクは進行中として扱う。内容は 200 文字以内でなければならず（MUST）、超える場合は保存を拒否する。タスク一覧は開始時刻の昇順で返さなければならない（SHALL）。

#### Scenario: 勤務日のタスク一覧を取得する

- **WHEN** ユーザーが 2026-10-09 のタスク一覧を要求する
- **THEN** システムは当日のタスクを開始時刻の昇順で返し、各タスクのジョブ ID・内容・開始・終了（進行中は空）を含める

#### Scenario: 内容が長すぎる

- **WHEN** ユーザーが 201 文字の内容でタスクを保存しようとする
- **THEN** システムは `422` を返し、タスクを保存しない

### Requirement: タスク開始

システムは「タスク開始」操作で、現在時刻を開始時刻とする進行中タスクを作成しなければならない（SHALL）。同じ勤務日に進行中のタスクまたは休憩がすでにある場合は、同じ時刻でそれを終了させてから新しいタスクを開始しなければならない（MUST）。同一勤務日に進行中のタスクは最大 1 件でなければならない（MUST）。

#### Scenario: 進行中タスクから別のタスクへ切り替える

- **WHEN** 09:00 開始の JOB-A のタスクが進行中で、10:30 に JOB-B で「タスク開始」する
- **THEN** システムは JOB-A を 10:30 で終了し、JOB-B を 10:30 開始の進行中タスクとして作成する

#### Scenario: 進行中タスクを 2 件作ろうとする

- **WHEN** 進行中タスクがある勤務日に、終了時刻なしのタスクを手入力で追加しようとする
- **THEN** システムは `409` を返し、新しいタスクを保存しない

### Requirement: タスク停止

システムは「停止」操作で、進行中タスクを現在時刻で終了させなければならない（SHALL）。

#### Scenario: 進行中タスクを停止する

- **WHEN** 13:00 開始の進行中タスクがあり、ユーザーが 16:30 に「停止」する
- **THEN** システムはそのタスクの終了時刻を 16:30 にし、当日の進行中タスクは 0 件になる

### Requirement: 時間帯の重なりの拒否

システムは、同一勤務日内でタスク同士、およびタスクと休憩の時間帯が重なる保存を拒否しなければならない（MUST）。拒否時は `409 Conflict` を返し、重なっている相手のレコードの種別・ID・時間帯を示さなければならない（MUST）。終了時刻と開始時刻が一致する隣接は重なりとみなしてはならない（MUST NOT）。

#### Scenario: タスク同士が重なる

- **WHEN** 13:00–14:00 のタスクがある日に、13:30–15:00 のタスクを保存しようとする
- **THEN** システムは `409` を返し、応答に重なっているタスクの ID と 13:00–14:00 を含める

#### Scenario: タスクと休憩が重なる

- **WHEN** 12:00–13:00 の休憩がある日に、11:30–12:30 のタスクを保存しようとする
- **THEN** システムは `409` を返し、応答に重なっている休憩の ID と時間帯を含める

#### Scenario: 隣接するタスク

- **WHEN** 09:00–10:30 のタスクがある日に、10:30–12:00 のタスクを保存する
- **THEN** システムはタスクを保存する

### Requirement: 過去日の手入力・編集・削除

システムは、当日・過去日を問わず、開始・終了時刻を手入力してタスクを追加・編集・削除できなければならない（SHALL）。編集時も重なりの検査を適用しなければならない（MUST）。終了時刻は開始時刻より後でなければならない（MUST）。

#### Scenario: 過去日にタスクを追加する

- **WHEN** ユーザーが 2026-10-09 の報告を開き、09:00–10:30・JOB-A・「設計レビュー」を入力して保存する
- **THEN** システムは 2026-10-09 のタスクとして保存し、一覧に表示する

#### Scenario: 終了が開始以前

- **WHEN** ユーザーが開始 10:00・終了 09:30 のタスクを保存しようとする
- **THEN** システムは `422` を返し、保存しない

#### Scenario: タスクを削除する

- **WHEN** ユーザーがタスクの削除を実行する
- **THEN** システムはそのタスクを削除し、一覧から除く

### Requirement: 勤務日を基準とした時刻入力

システムは、タスクと休憩の時刻を勤務日を基準とした `HH:MM` 形式で入力・表示しなければならない（SHALL）。`24:00`〜`29:59` は勤務日の翌日の時刻（アプリのタイムゾーン、既定 Asia/Tokyo）として扱わなければならない（SHALL）。勤務日の 00:00 より前、または翌日 06:00 以降の時刻は拒否しなければならない（MUST）。

#### Scenario: 日付をまたぐ終了時刻を入力する

- **WHEN** 2026-10-09 のタスクの終了時刻に `25:15` を入力する
- **THEN** システムは 2026-10-10 01:15（Asia/Tokyo）として保存し、表示時は `25:15` と表示する

#### Scenario: 範囲外の時刻を入力する

- **WHEN** 2026-10-09 のタスクの終了時刻に `30:00` を入力する
- **THEN** システムは入力エラーとし、保存しない
