# Spec Delta

## MODIFIED Requirements

### Requirement: 本日の報告画面

システムは、当日の始業・終業報告を行う「本日の報告」画面を提供しなければならない（SHALL）。当日の始業時刻・終業時刻・勤務時間・メモを表示し、記録操作の起点とする。画面には業務明細として、ジョブ選択・内容・開始時刻・終了時刻の入力と「追加」「休憩を追加」の操作、タスクと休憩を開始時刻順に並べた一覧（開始・終了・ジョブ・内容・時間、編集・削除）、作業と休憩の合計時間を表示しなければならない（SHALL）。進行中のタスク・休憩は終了時刻の代わりに進行中であることを示さなければならない（SHALL）。自由記述の「業務報告」入力欄は表示してはならず（MUST NOT）、代わりにメール作成の領域に `{{tasks}}` の展開結果を読み取り専用・コピー可能なプレビューとして表示しなければならない（SHALL）。カレンダーから過去日を開いた場合も、同じ画面でその日の業務明細を編集できなければならない（SHALL）。

#### Scenario: 本日の報告画面を表示する

- **WHEN** ユーザーが本日の報告画面を開く
- **THEN** システムは当日の日付、始業報告/終業報告の操作、記録済みの始業時刻・終業時刻・勤務時間・メモ、業務明細の操作と一覧、作業・休憩の合計時間を表示する

#### Scenario: カレンダーから本日の報告へ遷移する

- **WHEN** ユーザーがカレンダー上で本日の報告操作を選ぶ
- **THEN** システムは本日の報告画面を表示し、その場で始業・終業を記録できる

#### Scenario: 過去日の業務明細を編集する

- **WHEN** ユーザーがカレンダーで 2026-10-09 を選ぶ
- **THEN** システムは 2026-10-09 のタスクと休憩を一覧表示し、行の追加・編集・削除を受け付ける

#### Scenario: 重なる行も保存する

- **WHEN** ユーザーが既存の休憩と重なるタスクの行を保存する
- **THEN** システムは行を保存して一覧に表示し、重なりのエラーを表示しない

#### Scenario: 業務報告欄の代わりにプレビューを表示する

- **WHEN** ユーザーが本日の報告画面でメール作成の領域を見る
- **THEN** システムは自由記述の「業務報告」入力欄を表示せず、当日のタスクから生成した `{{tasks}}` のプレビューとコピー操作を表示する
