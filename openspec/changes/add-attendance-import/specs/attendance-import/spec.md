# Spec Delta

## Purpose

人事の出退勤実績を laborman の打刻とは別に保持し、人事メールからの自動取込と手入力の両方で登録できるようにして、zac 登録の正確な入力元とするための機能。

## ADDED Requirements

### Requirement: 出退勤実績の保持

システムは、勤務日ごとに出退勤実績（出勤時刻・退勤時刻・登録元・区分・取込日時・人事メール上の休憩分数）を、既存の打刻（`start_time`・`end_time`）とは別の項目として保持しなければならない（SHALL）。登録元は `hr_mail` または `manual`、区分は `work`（勤務）または `leave`（休暇）とし、未登録の日の区分は `work` とする。打刻の操作は出退勤実績を変更してはならない（MUST NOT）。

#### Scenario: 打刻と実績を別に保持する

- **WHEN** 2026-10-09 の打刻が 09:05–18:35 で、出退勤実績として 09:02–18:41 を登録する
- **THEN** システムは打刻と出退勤実績を両方保持し、報告の取得結果に別々の項目として返す

#### Scenario: 区分が勤務の実績は出勤・退勤が必須

- **WHEN** 区分 `work` で退勤時刻のない出退勤実績を登録しようとする
- **THEN** システムは `422` を返し、保存しない

### Requirement: 出退勤実績の手入力

システムは、UI から出退勤実績（出勤・退勤・区分）を手入力・上書きできなければならない（SHALL）。手入力した値の登録元は `manual` としなければならない（MUST）。出勤・退勤の入力には勤務日基準の `HH:MM` 形式（`24:00`〜`29:59` は翌日）を使う。

#### Scenario: 人事メール由来の値を手で直す

- **WHEN** 登録元 `hr_mail` の出勤 09:02 を、ユーザーが UI で 09:00 に修正して保存する
- **THEN** システムは出勤を 09:00、登録元を `manual` として保存する

### Requirement: 手入力値の保護

システムは、登録元 `manual` の出退勤実績がある勤務日に、登録元 `hr_mail` の登録要求を受けた場合、`409` を返し既存の値を変更してはならない（MUST NOT）。

#### Scenario: 手入力済みの日に人事メールの値が届く

- **WHEN** 2026-10-09 の出退勤実績が登録元 `manual` で、`hr_mail` の値を登録しようとする
- **THEN** システムは `409` を返し、`manual` の値を維持する

### Requirement: 人事メールからの取込

エージェントは、Outlook on the web をブラウザ自動化で開き、設定の検索条件（差出人・件名キーワード）に一致する実行日受信の人事メールを探し、本文から対象日の出勤・退勤時刻を抽出して、登録元 `hr_mail` として登録しなければならない（SHALL）。人事メールの検索条件は laborman の設定画面で編集できなければならない（SHALL）。本文の解析規則（行の書式・休暇の表記）は、コードを変更せずに設定で調整できなければならない（SHALL）。

#### Scenario: 前営業日の出退勤を取り込む

- **WHEN** 2026-10-12（月）に `laborman-agent fetch-attendance` を実行し、当日受信の人事メールに 10/9 の出勤 09:02・退勤 18:41 が書かれている
- **THEN** エージェントは 2026-10-09 の出退勤実績を 09:02–18:41・登録元 `hr_mail`・区分 `work` として登録し、取込日時を記録する

#### Scenario: 全角数字の時刻

- **WHEN** 人事メールの本文の時刻が全角数字（`０９：０２`）で書かれている
- **THEN** エージェントは半角に正規化して 09:02 として扱う

### Requirement: 人事メールの休憩の取込

エージェントは、人事メールに休憩が時間帯で書かれている場合、登録元 `hr_mail` の休憩として登録しなければならない（SHALL）。既存の休憩・タスクと重なる場合は登録せず、警告として通知しなければならない（MUST）。休憩が分数のみで書かれている場合は、休憩レコードを作らず、出退勤実績の休憩分数として保存しなければならない（SHALL）。

#### Scenario: 時間帯の休憩を取り込む

- **WHEN** 人事メールに対象日の休憩 12:00–13:00 が書かれ、対象日に重なる休憩・タスクがない
- **THEN** エージェントは登録元 `hr_mail` の休憩 12:00–13:00 を登録する

#### Scenario: 手入力の休憩と重なる

- **WHEN** 人事メールの休憩 12:00–13:00 が、手入力の休憩 12:15–13:15 と重なる
- **THEN** エージェントは人事メールの休憩を登録せず、重なりを警告として通知する

#### Scenario: 分数のみの休憩

- **WHEN** 人事メールに対象日の休憩が「60分」とだけ書かれている
- **THEN** エージェントは休憩レコードを作らず、出退勤実績の休憩分数を 60 として登録する

### Requirement: 休暇日の記録

エージェントは、人事メールに対象日の休暇の表記（設定の休暇キーワード。例：休暇・有給・代休）がある場合、その日の出退勤実績を区分 `leave` として登録しなければならない（SHALL）。区分 `leave` の日は出勤・退勤を空にできる。

#### Scenario: 有給の日

- **WHEN** 人事メールの 10/9 の行に「有給」と書かれている
- **THEN** エージェントは 2026-10-09 の出退勤実績を区分 `leave`・登録元 `hr_mail` として登録する

### Requirement: 人事メール未着時の扱い

エージェントは、検索条件に一致する人事メールが見つからない場合、DB を変更せず、「後で再試行」を示す終了コード `2` で終了しなければならない（MUST）。

#### Scenario: まだメールが届いていない

- **WHEN** 実行日に一致する人事メールが受信されていない状態で `fetch-attendance` を実行する
- **THEN** エージェントは出退勤実績を登録せず、終了コード `2` で終了する

### Requirement: 解析失敗時の扱い

エージェントは、本文から対象日の出退勤を解析できなかった場合、DB を変更せず、失敗を通知して人の対応が必要であることを示す終了コード `3` で終了しなければならない（MUST）。メール本文を laborman の DB に保存してはならない（MUST NOT）。調査用の本文はローカルのログディレクトリに所有者のみ読み書き可能な権限で保存し、保持期間（既定 14 日）を過ぎたら削除しなければならない（MUST）。

#### Scenario: 書式が変わったメール

- **WHEN** 人事メールの書式が変わり、対象日の出勤・退勤を抽出できない
- **THEN** エージェントは出退勤実績を登録せず、本文をログディレクトリに権限 `600` で保存し、解析失敗を通知して終了コード `3` で終了する

#### Scenario: 期限切れのデバッグ本文を削除する

- **WHEN** ログディレクトリに 15 日前に保存した本文がある状態でエージェントを実行する
- **THEN** エージェントはその本文を削除する
