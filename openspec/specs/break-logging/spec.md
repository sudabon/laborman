# break-logging Specification

## Purpose
勤務日ごとの休憩（開始・終了）を記録し、既定の休憩を自動で入れて、時刻を後から直すだけで済むようにするための機能。

## Requirements

### Requirement: 休憩の記録

システムは、勤務日ごとに休憩（開始時刻・終了時刻・登録元）を複数件記録し、追加・編集・削除できなければならない（SHALL）。終了時刻のない休憩は進行中として扱い、同一勤務日に進行中の休憩は最大 1 件でなければならない（MUST）。休憩にも、タスクと同じ勤務日基準の時刻入力を適用しなければならない（MUST）。タスクと重なる休憩も保存する（重なりは拒否しない）。手入力の休憩の登録元は `manual` とする。

#### Scenario: 過去日に休憩を追加する

- **WHEN** ユーザーが 2026-10-09 に 12:00–13:00 の休憩を入力して保存する
- **THEN** システムは登録元 `manual` の休憩として保存し、業務明細の一覧に「(休憩)」として表示する

#### Scenario: 休憩がタスクと重なる

- **WHEN** 11:00–12:30 のタスクがある日に 12:00–13:00 の休憩を保存する
- **THEN** システムは休憩を保存し、エラーを表示しない

### Requirement: 休憩開始・終了 API

システムは `POST /api/work-reports/{date}/breaks/start` で、進行中タスクを現在時刻で終了させ、現在時刻を開始時刻とする進行中の休憩を作成しなければならない（SHALL）。`POST /api/breaks/{id}/stop` で進行中の休憩を現在時刻で終了させなければならない（SHALL）。「本日の報告」画面はこれらの API を使わず、休憩開始・休憩終了の操作を表示してはならない（MUST NOT）。

#### Scenario: 作業中に API で休憩を開始する

- **WHEN** 09:00 開始の JOB-A のタスクが進行中で、12:00 に休憩開始 API を呼ぶ
- **THEN** システムは JOB-A を 12:00 で終了し、12:00 開始の進行中の休憩を作成する

### Requirement: 既定の休憩

システムは、設定で既定の休憩の開始・終了時刻（初期値 12:00–13:00）を保存・編集できなければならない（SHALL）。「本日の報告」画面で平日（月〜金）の勤務日を表示したとき、その日に休憩が 1 件もなく、出退勤実績の区分が休暇でなければ、システムは既定の休憩を登録元 `manual` として自動で追加しなければならない（SHALL）。自動で追加した休憩は、ほかの休憩と同じく開始・終了時刻を後から編集・削除できなければならない（SHALL）。既定の休憩がその日のタスクと重なる場合も追加する。休憩を削除した直後の再読込では追加せず、勤務日を表示し直したときにだけ追加する。

#### Scenario: 平日を開くと既定の休憩が入る

- **WHEN** 既定の休憩が 12:00–13:00 の設定で、休憩が 0 件の 2026-10-09（金）を本日の報告で開く
- **THEN** システムは 2026-10-09 に 12:00–13:00 の休憩を追加し、一覧に表示する

#### Scenario: 既定の休憩の時刻を直す

- **WHEN** 自動で追加された 12:00–13:00 の休憩を、ユーザーが 12:30–13:30 に編集して保存する
- **THEN** システムは休憩を 12:30–13:30 として保存し、次に開いたときも休憩は 1 件のまま追加しない

#### Scenario: 土日・休暇の日には入れない

- **WHEN** 休憩が 0 件の 2026-10-10（土）、または出退勤実績が休暇の平日を開く
- **THEN** システムは既定の休憩を追加しない

#### Scenario: 既定の休憩を変更する

- **WHEN** ユーザーが設定画面で既定の休憩を 11:45–12:45 に変更して保存する
- **THEN** システムは以降に自動で追加する休憩に 11:45–12:45 を使う
