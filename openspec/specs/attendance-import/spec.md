# attendance-import Specification

## Purpose
人事の出退勤実績を laborman の打刻とは別に保持し、人事メールからの自動取込と手入力の両方で登録できるようにして、zac 登録の正確な入力元とするための機能。

## Requirements

### Requirement: 出退勤実績の保持

システムは、勤務日ごとに出退勤実績（出勤時刻・退勤時刻・登録元・区分・取込日時）を、既存の打刻（`start_time`・`end_time`）とは別の項目として保持しなければならない（SHALL）。登録元は `hr_mail` または `manual`、区分は `work`（勤務）または `leave`（休暇）とし、未登録の日の区分は `work` とする。打刻の操作は出退勤実績を変更してはならない（MUST NOT）。

#### Scenario: 打刻と実績を別に保持する

- **WHEN** 2026-10-09 の打刻が 09:05–18:35 で、出退勤実績として 09:02–18:41 を登録する
- **THEN** システムは打刻と出退勤実績を両方保持し、報告の取得結果に別々の項目として返す

#### Scenario: 区分が勤務の実績は出勤・退勤が必須

- **WHEN** 区分 `work` で退勤時刻のない出退勤実績を登録しようとする
- **THEN** システムは `422` を返し、保存しない

#### Scenario: 人事メールから休暇は登録できない

- **WHEN** 登録元 `hr_mail`・区分 `leave` の出退勤実績を登録しようとする
- **THEN** システムは `422` を返し、保存しない

### Requirement: 出退勤実績の手入力

システムは、UI から出退勤実績（出勤・退勤・区分）を手入力・上書きできなければならない（SHALL）。手入力した値の登録元は `manual` としなければならない（MUST）。出勤・退勤の入力には勤務日基準の `HH:MM` 形式（`24:00`〜`29:59` は翌日）を使う。

#### Scenario: 人事メール由来の値を手で直す

- **WHEN** 登録元 `hr_mail` の出勤 09:02 を、ユーザーが UI で 09:00 に修正して保存する
- **THEN** システムは出勤を 09:00、登録元を `manual` として保存する

### Requirement: 手入力値の保護

システムは、登録元 `manual` の出退勤実績がある勤務日に、登録元 `hr_mail` の登録要求を受けた場合、`409` を返し既存の値を変更してはならない（MUST NOT）。

#### Scenario: 手入力済みの日に人事メールの値が届く

- **WHEN** 2026-10-09 の出退勤実績が登録元 `manual` で、`hr_mail` の値を登録しようとする
- **THEN** システムは `409` を返し、`manual` の値を維持する

### Requirement: 人事メールからの取込

エージェントは、Outlook on the web をブラウザ自動化で開き、件名キーワードと対象日（`YYYY/MM/DD`）で人事メールを検索し（差出人が設定されていれば条件に加える）、件名（`[勤怠情報]YYYY/MM/DD:開始HH:MM/終了HH:MM`）から対象日の出勤・退勤時刻を抽出して、登録元 `hr_mail`・区分 `work` として登録しなければならない（SHALL）。件名から抽出できない場合は、本文の `対象日`・`開始時間`・`終了時間` から抽出しなければならない（SHALL）。受信日で絞り込んではならない（MUST NOT）。抽出した対象日が指定の対象日と一致しない場合は、解析失敗として扱わなければならない（MUST）。本文の `残業時間` は取り込んではならない（MUST NOT）。人事メールの検索条件（件名キーワード・差出人）は laborman の設定画面で編集できなければならない（SHALL）。解析規則は、コードを変更せずに設定で調整できなければならない（SHALL）。

#### Scenario: 前営業日の出退勤を件名から取り込む

- **WHEN** 2026-10-13（火）に `laborman-agent fetch-attendance` を実行し、件名 `[勤怠情報]2026/10/09:開始08:29/終了18:38` の人事メールがある
- **THEN** エージェントは 2026-10-09 の出退勤実績を 08:29–18:38・登録元 `hr_mail`・区分 `work` として登録し、取込日時を記録する

#### Scenario: 件名で解析できず本文から取り込む

- **WHEN** 対象日 2026-10-09 の人事メールの件名が書式に合わず、本文に `対象日` `2026/10/09`・`開始時間` `08:29`・`終了時間` `18:38` がそれぞれ別の行で書かれている
- **THEN** エージェントは本文から 08:29–18:38 を抽出して登録する

#### Scenario: 遅れて届いたメールを取り込む

- **WHEN** `--date 2026-10-08` を指定して実行し、2026-10-08 分の人事メールが 2 営業日後に受信されている
- **THEN** エージェントは受信日によらずそのメールを見つけ、2026-10-08 の出退勤実績を登録する

#### Scenario: 対象日と異なる日のメール

- **WHEN** 対象日 2026-10-09 の検索結果に、件名の日付が 2026/10/08 のメールしかない
- **THEN** エージェントは出退勤実績を登録しない

#### Scenario: 全角数字の時刻

- **WHEN** 人事メールの時刻が全角数字（`０８：２９`）で書かれている
- **THEN** エージェントは半角に正規化して 08:29 として扱う

### Requirement: 休暇日の記録

休暇の日は人事メールが届かないため、システムは、ユーザーが UI で区分 `leave`（登録元 `manual`）を登録できるようにしなければならない（SHALL）。区分 `leave` の日は出勤・退勤を空にできる。エージェントは、区分 `leave` の日を含む登録元 `manual` の日について、OWA を開かずに取込をスキップしなければならない（SHALL）。半休の日は特別扱いせず、人事メールの出退勤をそのまま登録する。

#### Scenario: 休暇を手入力した日

- **WHEN** 2026-10-09 の出退勤実績を区分 `leave`・登録元 `manual` で登録済みの状態で、`fetch-attendance --date 2026-10-09` を実行する
- **THEN** エージェントは OWA を開かず、出退勤実績を変更せずに終了コード `0` で終了する

### Requirement: 人事メール未着時の扱い

エージェントは、検索条件に一致する人事メールが見つからない場合、DB を変更せず、「後で再試行」を示す終了コード `2` で終了しなければならない（MUST）。

未着の場合の出力（通知する場合は通知も）には、休暇の日であれば UI で休暇として登録するよう案内を含めなければならない（SHALL）。

#### Scenario: まだメールが届いていない

- **WHEN** 対象日の人事メールが受信されていない状態で `fetch-attendance` を実行する
- **THEN** エージェントは出退勤実績を登録せず、休暇登録の案内を出力して終了コード `2` で終了する

### Requirement: 解析失敗時の扱い

エージェントは、本文から対象日の出退勤を解析できなかった場合、DB を変更せず、失敗を通知して人の対応が必要であることを示す終了コード `3` で終了しなければならない（MUST）。メール本文を laborman の DB に保存してはならない（MUST NOT）。調査用の本文はローカルのログディレクトリに所有者のみ読み書き可能な権限で保存し、保持期間（既定 14 日）を過ぎたら削除しなければならない（MUST）。

#### Scenario: 書式が変わったメール

- **WHEN** 人事メールの書式が変わり、対象日の出勤・退勤を抽出できない
- **THEN** エージェントは出退勤実績を登録せず、本文をログディレクトリに権限 `600` で保存し、解析失敗を通知して終了コード `3` で終了する

#### Scenario: 期限切れのデバッグ本文を削除する

- **WHEN** ログディレクトリに 15 日前に保存した本文がある状態でエージェントを実行する
- **THEN** エージェントはその本文を削除する
